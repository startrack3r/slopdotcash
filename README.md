# PR #2338 publication benchmark

Review evidence for [SlopDotCash/slopdotcash#2338](https://github.com/SlopDotCash/slopdotcash/pull/2338).
This is a separate evidence branch; these files are outside the contribution diff.

The real Points generator produced 27,416 revisions for 935 contributors on both revisions. Median local publication time fell from 3422.66 ms to 3172.46 ms (7.3%). All 20 publication outputs matched SHA-256 in every run.

- [Results](results.json): original measured samples, combined medians and output hashes.
- [Process runs](runs.json): original samples and output hashes, in base/fix/fix/base/base/fix order. Each process ran one warm-up and two measured publications.
- [Input manifest](inputs.json): digests of the public registry snapshot and prepared public leaderboard. Compressed copies are in `inputs/`. Other retained inputs come from the pinned source commits.

Only the publication clock is fixed, at `2026-11-05T19:00:00.000Z`, so generated bytes are comparable. The measurement includes file reads, validation, hashing, aggregation and file writes. Module import is outside the timed call. No delay, network request, provider call or mocked model result is involved. This is local publication performance, not production latency or live ingestion.

## Reproduce

Use a disposable checkout: restoring inputs overwrites the two generated registry files and `public/data/leaderboard.json`. The benchmark writes the ordinary ignored Points publication outputs. Do not run `projects:sync` or rebuild the leaderboard between restoring these pinned inputs and benchmarking.

1. Check out the base or head above, then run `bun install --frozen-lockfile`.
2. From any directory, run `node /absolute/path/to/evidence/restore-inputs.mjs /absolute/path/to/checkout`.
3. In the checkout root, run `bun /absolute/path/to/evidence/benchmark.mjs /absolute/path/to/result.json`.
4. Repeat in separate processes in base/fix/fix/base/base/fix order. Each invocation performs one warm-up and two measured runs. Combine the six measured samples per revision and take their median. Timing varies by machine; the driver enforces all 20 original output digests on every publication.

The published driver uses the same timed operation as the original measurement. Its import paths are portable, it checks the pinned input/output digests, and it calculates the conventional median for both odd and even sample counts. The original samples in `results.json` and `runs.json` are unchanged. A subsequent [driver validation](validation.json) ran it in a fresh checkout at the head and then the base, reproducing all 20 original output digests on each run. Those validation timings are not substituted for the original benchmark.

The PR records the complete verification commands and their failures. This artifact does not claim a green full test suite, deployed performance, accepted work or completed Slop registration.
